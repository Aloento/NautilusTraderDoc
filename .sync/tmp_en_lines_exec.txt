1710|### Ambiguous outcome failures
1712|These cases prove that adapter request failures do not turn into terminal rejection events when the venue
1713|outcome is unknown. The pass criteria also define an exception for local prepare failures. The command must be
1714|known not to have been sent. The failure must be attributable to one cancel or modify command. If both
1715|conditions hold, the adapter can emit the matching rejection event.

1720|  response parse failures do not emit `OrderRejected`.

1722|  whole-request server failures do not emit `OrderCancelRejected`.
1723|- Modify failures from transport errors, timeouts, WebSocket send failures, retry exhaustion, or
1724|  whole-request server failures do not emit `OrderModifyRejected`.

1726|  `OrderCancelRejected` when the adapter can attribute the failure to one cancel command.

1728|  `OrderModifyRejected` when the adapter can attribute the failure to one modify command.

1730|  per-order results.

1732|  reason.
