快速开始

1. 安装​

准备一个 Python 3.13-3.14 环境，安装包：

pip install -U --pre nautilus_trader

PyPI 上的 NautilusTrader 2.x 以 2.0.0rcN 预发布版本提供。在 2.0.0 正式发布前都要加 --pre。用下面的命令确认安装结果：

python -c "import nautilus_trader; print(nautilus_trader.__version__)"

平台支持范围与源码构建见安装指南。

2. 运行快速上手​

快速上手用合成数据带你五分钟内跑通第一个回测， 无需下载数据，也不必配置数据目录。

入门教程都使用同一个简单的 EMA 交叉策略，这是有意为之——交易逻辑不是重点， 这些教程要讲的是引擎的运转方式：数据加载、场所模拟、订单生命周期与报告。 引擎机制熟悉之后，教程会引入别的策略（均值回归、 订单簿失衡、网格做市）。

3. 选择路线​

  • 回测——先了解下文两种 API 层级，再按教程 过一遍策略模式讲解。
  • 实时交易——看配置实时交易节点 与集成，了解支持的场所。
  • 数据工作流——操作指南讲如何加载外部数据、 搭建 Parquet 数据目录。
  • 编写适配器——见开发者指南。

回测 API 层级​

NautilusTrader 提供两种回测 API 层级：

API 层级入口适用场景
低层 APIBacktestEngine直接操作组件、开发库
高层 APIBacktestNode生产工作流，便于过渡到实时交易（推荐）

高层 API 要求基于 Parquet 的数据目录；低层 API 可直接处理内存数据，但没有对应的实时交易路径。

一个进程一个节点

受全局单例状态限制，同一进程内并发运行多个 BacktestNode 或 LiveNode 实例不受支持。顺序执行、两次运行之间正确释放资源是可以的。 同一线程上构建替代的 LiveNode 前，也要先丢弃旧节点， 或在 Python 中释放对它的引用。

细节见进程与线程。

如何选择 API 层级，见回测概念指南。

在 Docker 中运行​

自带 Jupyter notebook 服务器的 Docker 镜像是零本地配置体验 NautilusTrader 最快的方式。删除容器时，其中数据一并删除。

# Pull the latest image
docker pull ghcr.io/nautechsystems/jupyterlab:nightly --platform linux/amd64

# Run the container
docker run -p 8888:8888 ghcr.io/nautechsystems/jupyterlab:nightly

然后在浏览器打开 http://localhost:8888。

注意

示例中统一使用 LoggerConfig(stdout_level=LogLevel.ERROR)：Nautilus 的日志量会超出 Jupyter 的 stdout 速率上限，日志级别更低时 notebook 会卡住。
