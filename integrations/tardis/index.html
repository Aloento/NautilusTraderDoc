Tardis

Tardis 提供细粒度的加密货币行情数据，包括逐笔订单簿快照与增量、成交、未平仓合约量、资金费率、期权摘要 和平仓数据。

NautilusTrader 集成了 Tardis API、Tardis Machine WebSocket 服务器和 Tardis CSV 格式。该适配器的能力包括：

  • CSV 加载与流式函数把 Tardis 格式的文件批量或有界分块地读入为 Nautilus 数据。
  • run_tardis_machine_replay 回放历史数据并写出 Nautilus Parquet catalog 文件。
  • TardisDataClientConfig 与 TardisDataClientFactory 把 Nautilus 节点连接到配置好的历史回放或 实时 Tardis Machine 数据流。
  • Python 与 Rust 均暴露 TardisMachineClient 和 TardisHttpClient，用于更底层地访问归一化数据流 与金融工具元数据。
信息

Nautilus 的金融工具元数据调用需要 TARDIS_API_KEY。Tardis Machine 在访问每月免费首日之外的历史日期时 使用 TM_API_KEY。另见环境变量。

概览​

该适配器用 Rust 实现，附带可选的 Python 绑定。其组件编译进 NautilusTrader，因此无需单独安装 Tardis 客户端库。上游 API、格式与服务器请查阅 Tardis 文档。

Tardis Machine 使用的最低已测试 Tardis Node 版本为 18.2.2。该版本修复了 Deribit 订单簿归一化中的 一个问题：已被快照覆盖的排队增量在快照之后到达时的处理。NautilusTrader 不会在你的 Tardis Machine 部署中锁定版本。

支持的格式​

Tardis 提供归一化行情数据，一种在各支持交易所间统一的格式。这一归一化让同一个解析器能处理来自任何 Tardis 支持的交易所的数据。本适配器不支持交易所原生格式的 Tardis 行情数据。

NautilusTrader 支持下列归一化的 Tardis Machine 格式。字段 schema 见官方 Tardis 数据类型参考。

Tardis 格式Nautilus 数据类型
book_changeOrderBookDeltas
book_snapshot_*OrderBookDepth 或 OrderBookDeltas
quoteQuoteTick
quote_10sQuoteTick
tradeTradeTick
trade_bar_*Bar
derivative_tickerFundingRateUpdate、MarkPriceUpdate 或 IndexPriceUpdate
option_summaryOptionGreeks；可由 BBO 字段产生可选的 QuoteTick
disconnect忽略

说明：

  • Tardis 文档把 quote 记为 book_snapshot_1_0ms 的别名。
  • Tardis 文档把 quote_10s 记为 book_snapshot_1_10s 的别名。
  • quote、quote_10s 和单档快照按 QuoteTick 解析。
  • 数据客户端只在数值变化时，才从 derivative_ticker 消息发出资金费率、标记价格与指数价格更新。 catalog 回放流水线不写这些更新。
  • Tardis 的 option_summary 消息包含最优买卖价字段。Nautilus 总是把该数据流映射为 OptionGreeks。设 extract_bbo_as_quotes 为 true 可同时从这些 BBO 字段发出 QuoteTick。
  • 适配器不解析 Tardis 的 book_ticker、liquidation 或 error 归一化格式。
信息

另见 Tardis 的 Tardis Machine 快速上手。

能整除小时或天的分钟间隔使用规范的 Nautilus HOUR 或 DAY 聚合。

环境变量​

Tardis 与 NautilusTrader 使用以下环境变量。

  • TM_API_KEY：传给 Tardis Machine 进程、用于访问历史数据的 API key。
  • TARDIS_API_KEY：Nautilus 金融工具元数据请求用的 API key。
  • TARDIS_MACHINE_WS_URL（可选）：Tardis Machine WebSocket 基础 URL。
  • NAUTILUS_PATH（可选）：包含回放输出用 catalog/ 子目录的父目录。

Tardis 金融工具元数据 API 需要 bearer token 鉴权，仅对有效的 pro 与 business Tardis 订阅开放。

运行 Tardis Machine 历史回放​

Tardis Machine Server 是一个可本地运行、 内置数据缓存的服务器。它通过 HTTP 与 WebSocket API 提供 tick 级的历史与合并后的实时加密货币行情数据。

注意

若在完成之前取消历史 WebSocket 回放，Tardis Machine 18.2.2 可能终止。该问题出现在 Node.js 26.7.0 上运行的 Tardis Node 18.2.3。回放可能留着缓存文件句柄不关闭，垃圾回收关闭它时 引发 ERR_INVALID_STATE 错误。服务器退出还会中断其他已连接的客户端。

尽可能让回放自然结束。同一服务器跑在 Node.js 24.19.0 上可避开观测到的崩溃，但仍会产生 DEP0137 警告。这并没有修复上游的文件句柄泄漏。

你可以从 Python 或 Rust 运行完整的 Tardis Machine WebSocket 回放，并以 Nautilus Parquet 格式写出 结果。两种接口调用的是同一个 Rust 回放实现。

端到端的数据流水线函数 run_tardis_machine_replay 按指定的配置执行以下步骤：

  • 连接 Tardis Machine 服务器。
  • 从 Tardis 金融工具元数据 API 请求并解析所配置交易所的全部金融工具定义。
  • 从 Tardis Machine 按指定时间范围流式获取所有请求的金融工具与数据类型。
  • 按数据类型与日期（UTC），以金融工具或 bar type 写出与 catalog 兼容的 .parquet 文件。
  • 结束数据流并把剩余数据刷写到磁盘。

输出文件​

文件按 UTC 每个交易日、每个金融工具一个（或按 bar type 一个）写出，文件名用 ISO 8601 时间戳范围：

  • 格式：{start_timestamp}_{end_timestamp}.parquet
  • 示例：2023-10-01T00-00-00-000000000Z_2023-10-01T23-59-59-999999999Z.parquet
  • 相对路径：{data_type}/{instrument_id}/{filename}；K 线则为 bars/{bar_type}/{filename}。

该格式与 Nautilus 数据 catalog 的查询、合并与管理兼容。

备注

每月第一天的数据无需 Tardis Machine API key 即可请求。其他日期需要 TM_API_KEY。

该流程针对直接输出到 Nautilus Parquet 数据 catalog 做了优化。 把 NAUTILUS_PATH 设为包含 catalog/ 子目录的父目录。Parquet 文件写入 <NAUTILUS_PATH>/catalog/data/ 下，按数据类型与金融工具或 bar type 分子目录。

若既未指定 output_path 也未设置 NAUTILUS_PATH，输出默认为当前工作目录。

步骤​

注意

不要把 Tardis Machine 端口发布到主机地址 0.0.0.0。端口映射省略主机地址时，Docker 默认在所有主机接口上发布端口。 在 Linux 上，Docker 会在 ufw 应用规则之前转移已发布的容器流量， 可能绕过预期的防火墙限制。除非确实需要并另行加固了远程访问，两个端口都应绑定 127.0.0.1。

对于每月免费首日之外的日期，先在主机环境中设置 TM_API_KEY，再启动 tardis-machine Docker 容器：

docker run \
  -p 127.0.0.1:8000:8000 \
  -p 127.0.0.1:8001:8001 \
  -e TM_API_KEY \
  -d tardisdev/tardis-machine

该命令启动的 tardis-machine 服务器没有持久化本地缓存，可能影响性能。要获得更好的回放性能， 请配合持久卷运行。

配置​

接下来，确保手边有一份配置 JSON 文件。

配置 JSON 字段

  • tardis_ws_url（str | null）：Tardis Machine WebSocket URL。默认为 TARDIS_MACHINE_WS_URL。
  • tardis_http_url（str | null）：Tardis HTTP API 基础 URL。默认为 https://api.tardis.dev/v1。
  • normalize_symbols（bool | null）：应用 Nautilus 符号归一化。默认为 true。
  • output_path（str | null）：Parquet 数据的输出目录。未设置时，若 NAUTILUS_PATH 已设则用 <NAUTILUS_PATH>/catalog/data，否则用当前工作目录。
  • book_snapshot_output（"deltas" | "depth" | null）：快照的输出格式。默认 "deltas"。
  • extract_bbo_as_quotes（bool | null）：同时从 Tardis Machine option_summary 消息的 最优买卖价字段写出 QuoteTick 数据。默认为 false。
  • compression（"zstd" | "snappy" | "uncompressed" | null）：Parquet 压缩编解码器。 默认为 "zstd" 3 级。
  • proxy_url（str | null）：Tardis HTTP 请求的代理 URL。默认不使用代理。
  • options（JSON[]）：必需的回放请求选项对象。

示例配置文件位于 crates/adapters/tardis/bin/example_config.json：

{
  "tardis_ws_url": "ws://localhost:8001",
  "output_path": null,
  "options": [
    {
      "exchange": "bitmex",
      "symbols": [
        "xbtusd",
        "ethusd"
      ],
      "data_types": [
        "trade"
      ],
      "from": "2019-10-01",
      "to": "2019-10-02"
    }
  ]
}

订单簿快照输出​

配置项 book_snapshot_output 控制 Tardis book_snapshot_* 消息如何转换与存储。

值Nautilus 类型输出目录说明
deltasOrderBookDeltasorder_book_deltas/每个快照转为清空加逐档新增增量。
depthOrderBookDepthorder_book_depths/含全部价位档的快照。

各格式的适用场景：

  • deltas（默认）：需要重建订单簿状态、或把快照与 book_change 数据合并时使用。 每个快照变成一个清空增量，随后每档一个新增增量。
  • depth：策略需要周期性深度快照时使用。每个快照是包含交易场所消息中全部价位档的 单条记录。

避免文件覆盖：

对同一金融工具、同一日期范围同时下载 book_snapshot_* 与 book_change 数据时， depth 把快照写到 order_book_depths/，避免覆盖 order_book_deltas/。

显式指定格式的示例配置：

{
  "tardis_ws_url": "ws://localhost:8001",
  "book_snapshot_output": "depth",
  "options": [
    {
      "exchange": "binance-futures",
      "symbols": ["btcusdt"],
      "data_types": ["book_snapshot_5_100ms", "book_change"],
      "from": "2024-01-01",
      "to": "2024-01-02"
    }
  ]
}

期权摘要 BBO 提取​

请求 Tardis Machine 的 option_summary 数据且回测同时需要期权 BBO 报价时，把 extract_bbo_as_quotes 设为 true。Nautilus 仍会为每条 option_summary 消息写出 OptionGreeks。当最优买卖价字段齐全且数量有效时，还会为同一金融工具与时间戳写出一个 QuoteTick。

该选项只作用于 Tardis Machine 的 option_summary 回放与流式消息，不改变 Tardis CSV 加载。

{
  "tardis_ws_url": "ws://localhost:8001",
  "extract_bbo_as_quotes": true,
  "options": [
    {
      "exchange": "deribit",
      "symbols": ["BTC-28JUN24-70000-C"],
      "data_types": ["option_summary"],
      "from": "2024-01-01",
      "to": "2024-01-02"
    }
  ]
}

Python 回放​

在 Python 中运行回放，创建一个类似下面的脚本：

import asyncio
from pathlib import Path

from nautilus_trader.adapters.tardis import run_tardis_machine_replay


async def run():
    config_filepath = Path("YOUR_CONFIG_FILEPATH")
    await run_tardis_machine_replay(str(config_filepath.resolve()))


if __name__ == "__main__":
    asyncio.run(run())

Rust 回放​

在 Rust 中运行回放，启用 nautilus-tardis 的 replay feature flag，并创建一个类似下面的二进制：

use std::path::PathBuf;

use nautilus_tardis::replay::run_tardis_machine_replay_from_config;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    nautilus_common::logging::ensure_logging_initialized();

    let config_filepath = PathBuf::from("YOUR_CONFIG_FILEPATH");
    run_tardis_machine_replay_from_config(&config_filepath).await?;
    Ok(())
}

日志默认为 INFO 级别。要启用调试日志，导出以下环境变量：

export NAUTILUS_LOG=debug

一个可运行的示例二进制位于 crates/adapters/tardis/bin/example_replay.rs。

也可以用 cargo 运行：

cargo run -p nautilus-tardis --features replay --bin tardis-replay <path_to_your_config>

期权链回测 catalog​

期权链回测在 Tardis 回放把数据写入 Nautilus catalog 之后才能开始。回测加载器不会在运行期间 请求补齐缺失的 Tardis 数据，因此 catalog 必须包含：

  • 来自 Tardis 金融工具元数据 API 的期权金融工具。
  • 来自单层期权订单簿快照、报价数据或 option_summary BBO 提取的 QuoteTick 数据。
  • 来自 Tardis option_summary 消息的 OptionGreeks 数据。

对同一批期权金融工具 ID，在 BacktestDataConfig 列表中同时使用 QuoteTick 与 OptionGreeks。期权链管理器把回放的 BBO 与 Greeks 聚合为 OptionChainSlice 快照。 原始发布用 snapshot_interval_ms=None；设置毫秒级间隔则发布抽稀后的快照。

策略可以用 ATM 相对或 ATM 百分比行权价区间按价内程度选合约，用 StrikeRange.delta(target, tolerance) 按 delta 选，或用 StrikeRange.fixed([...]) 按固定行权价选。回测中的期权订单撮合是报价驱动的： 可成交订单作为 taker 对着对手方 BBO 成交；当后续 BBO 更新穿过限价时，被动限价单可以作为 maker 成交。

在模拟交易场所上用结构化费用模型（如 CappedOptionFeeModel 或 TieredNotionalOptionFeeModel） 显式配置期权费用。不存在从 Tardis 交易所到费用模型的自动映射。

期权链 CSV catalog 转换​

对于来自可下载 Tardis CSV 文件的历史期权链，用 convert_tardis_options_chain_csv(...) 把 options_chain 行转换为 Nautilus catalog 数据。这条路径既不调用 Tardis Machine，也不调用 金融工具元数据 API。可配合已有的 Tardis CSV 文件使用，或在没有 API key 时从下载的数据引导 建立 catalog。

转换器为每个选中的行写出 OptionGreeks。默认 extract_bbo_as_quotes=True 时，最优买卖价 完整的行还会写出 QuoteTick。期权链回测请保持该选项开启。仅含 Greeks 的 catalog 不提供报价， 因此对没有 BBO 数据的行权价，链管理器无法发布内容完整的 OptionChainSlice 快照。

金融工具推导目前仅支持 Deribit 期权。对其他期权交易场所，转换前先设 write_instruments=False， 并在回测前通过其他来源加载金融工具。对非 Deribit 文件保持该选项开启时，可能在数据文件已写入 catalog 之后才失败。

按时间顺序传入逐日的 options_chain CSV 路径。underlyings 过滤器匹配符号前缀， 如 ["BTC-"]。要在每个输入文件内按间隔保留每个金融工具的最后一行，设置 snapshot_interval_ms；或设为 None 写出每个选中行。抽稀时文件内的行必须按 local_timestamp 排序。

显式提供 price_precision 与 size_precision 以获得确定性的报价元数据。推断出的精度 会随着后续行被读取而升高，因此文件前部写入的数据可能保留较低精度的元数据。

from pathlib import Path

from nautilus_trader.adapters.tardis import convert_tardis_options_chain_csv


convert_tardis_options_chain_csv(
    filepaths=[Path("deribit_options_chain_2020-06-08.csv")],
    catalog_path=Path("catalog"),
    underlyings=["BTC-"],
    snapshot_interval_ms=60_000,
    price_precision=4,
    size_precision=1,
)

加载 Tardis CSV 数据​

Tardis 格式的 CSV 数据可以用 Python 或 Rust 加载。加载器从磁盘读取 CSV 文本数据并解析为 Nautilus 数据。两种接口调用同一个 Rust 加载器。

load_* 函数还可以指定 limit 参数来控制加载的最大行数。

按 Tardis FAQ，增量加载器与流式函数会跳过文件中 第一个快照行之前的所有行。被裁剪或拆分过、不再以快照行开头的 CSV 会产生零个增量。

备注

由于精度要求，加载混合金融工具的 CSV 文件很有挑战，不推荐这样做。请改用单金融工具的 CSV 文件。

load_tardis_options_chain、stream_tardis_options_chain 和 convert_tardis_options_chain_csv 函数是例外：Tardis 的 options_chain 文件本身就是混合 金融工具的链文件，这些路径会按金融工具分别跟踪精度。为获得确定性输出，仍推荐显式精度。

在 Python 中加载 CSV 数据​

在 Python 中可用模块级的 load_tardis_* 函数加载 Tardis 格式的 CSV 数据。加载数据时可以选择 指定金融工具 ID、价格精度和数量精度。提供金融工具 ID 能提升加载性能。省略精度时从 CSV 推断， 但推荐显式指定以获得确定性输出，尤其是大文件。

要加载数据，创建一个类似下面的脚本：

from pathlib import Path

from nautilus_trader.adapters.tardis import load_tardis_deltas
from nautilus_trader.model import InstrumentId


instrument_id = InstrumentId.from_str("BTC-PERPETUAL.DERIBIT")
deltas = load_tardis_deltas(
    filepath=Path("YOUR_CSV_DATA_PATH"),
    price_precision=1,
    size_precision=0,
    instrument_id=instrument_id,
)

在 Rust 中加载 CSV 数据​

在 Rust 中可用 crates/adapters/tardis/src/csv/mod.rs 里的加载函数加载 Tardis 格式的 CSV 数据。 加载时可以选择指定金融工具 ID、价格精度和数量精度。提供金融工具 ID 能提升加载性能。省略精度时 从 CSV 推断，但推荐显式指定以获得确定性输出。

完整示例见 crates/adapters/tardis/bin/example_csv.rs。

加载数据可以用类似下面的代码：

use std::path::Path;

use nautilus_model::identifiers::InstrumentId;
use nautilus_tardis::csv::load_deltas;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Optionally specify precisions and the CSV filepath
    let price_precision = Some(1);
    let size_precision = Some(0);
    let filepath = Path::new("YOUR_CSV_DATA_PATH");

    // Optionally specify an instrument ID and/or limit
    let instrument_id = InstrumentId::from("BTC-PERPETUAL.DERIBIT");
    let limit = None;

    let _deltas = load_deltas(
        filepath,
        price_precision,
        size_precision,
        Some(instrument_id),
        limit,
    )?;
    Ok(())
}

流式读取 Tardis CSV 数据​

Tardis 集成可以按可配置的分块加载并处理大型 CSV 文件。这样无需把整个文件载入内存或耗尽系统内存， 就能处理数 GB 的文件。

Python 为下列 CSV 数据提供流式函数：

  • 订单簿增量（stream_tardis_deltas 与 stream_tardis_batched_deltas）。
  • 订单簿深度快照（stream_tardis_depth_from_snapshot5 与 stream_tardis_depth_from_snapshot25）。
  • 报价 tick（stream_tardis_quotes）。
  • 成交 tick（stream_tardis_trades）。
  • 资金费率（stream_tardis_funding_rates）。
  • 期权链行（stream_tardis_options_chain）。

Rust 暴露等价的 stream_* 函数。

在 Python 中流式读取 CSV 数据​

模块级的 stream_tardis_* 函数返回有界分块的迭代器。chunk_size 参数接受 [1, 1_000_000] 内的值，控制每块读取的记录数：

from pathlib import Path

from nautilus_trader.adapters.tardis import stream_tardis_trades
from nautilus_trader.model import InstrumentId

instrument_id = InstrumentId.from_str("BTC-PERPETUAL.DERIBIT")
filepath = Path("large_trades_file.csv")

trades = stream_tardis_trades(
    filepath=filepath,
    chunk_size=100_000,
    price_precision=1,
    size_precision=0,
    instrument_id=instrument_id,
)

# Stream trade ticks in chunks
for chunk in trades:
    print(f"Processing chunk with {len(chunk)} trades")
    # Process each chunk - only this chunk is in memory
    for trade in chunk:
        # Your processing logic here
        pass

流式读取订单簿数据​

订单簿数据的流式读取对增量和深度快照都可用：

from pathlib import Path

from nautilus_trader.adapters.tardis import stream_tardis_deltas
from nautilus_trader.adapters.tardis import stream_tardis_depth_from_snapshot5


filepath = Path("book_snapshot_5.csv")

# Stream order book deltas
for chunk in stream_tardis_deltas(filepath):
    print(f"Processing {len(chunk)} deltas")
    # Process delta chunk

# Stream depth snapshots from snapshot_5 files
for chunk in stream_tardis_depth_from_snapshot5(filepath):
    print(f"Processing {len(chunk)} depth snapshots")
    # Process depth chunk

流式读取报价数据​

报价数据的流式读取方式类似：

from pathlib import Path

from nautilus_trader.adapters.tardis import stream_tardis_quotes


filepath = Path("quotes.csv")

# Stream quote ticks
for chunk in stream_tardis_quotes(filepath):
    print(f"Processing {len(chunk)} quotes")
    # Process quote chunk

内存使用​

流式读取限制了同一时刻保留的已解析记录数：

  • 内存占用可控：同一时刻只把一个分块载入内存。
  • 大文件处理：迭代器可以处理大于可用 RAM 的文件。
  • 分块大小可配置：根据系统的内存与性能需求在 [1, 1_000_000] 内调节 chunk_size（默认 100,000）。
注意

使用流式读取并依赖精度推断时，推断出的精度可能与整体加载整个文件不同。精度推断只在分块 边界内起作用，不同分块可能包含精度要求不同的值。要获得确定性的精度行为，请显式提供 price_precision 与 size_precision 参数。

在 Rust 中流式读取 CSV 数据​

底层流式功能用 Rust 实现，可直接使用：

use std::path::Path;

use nautilus_model::identifiers::InstrumentId;
use nautilus_tardis::csv::stream_trades;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let filepath = Path::new("large_trades_file.csv");
    let chunk_size = 100_000;
    let price_precision = Some(1);
    let size_precision = Some(0);
    let instrument_id = Some(InstrumentId::from("BTC-PERPETUAL.DERIBIT"));

    // Stream trades in chunks
    let stream = stream_trades(
        filepath,
        chunk_size,
        price_precision,
        size_precision,
        instrument_id,
    )?;

    for chunk in stream {
        let chunk = chunk?;
        println!("Processing chunk with {} trades", chunk.len());
        // Process chunk
    }

    Ok(())
}

金融工具元数据​

回放流水线与数据客户端在连接 Tardis Machine 之前，会为所配置 Tardis options 中的每个交易所请求 元数据。它们使用 Tardis 金融工具元数据 API 把金融工具元数据解析为 Nautilus 定义。数据客户端还会把这些定义发布到 Nautilus 数据引擎。

备注

需要有效 Tardis pro 或 business 订阅的 TARDIS_API_KEY。自动引导会为每个配置的 Tardis 交易所 请求全部金融工具元数据。

Python 与 Rust 用户也可以直接用 TardisHttpClient 请求金融工具定义。该客户端接受可选的 api_key、base_url、timeout_secs、normalize_symbols 和 proxy_url 参数。它可以获取 单个符号或某交易所的全部金融工具。请使用 Tardis 的小写连字符交易所 ID，如 binance-futures。

在 Python 中请求金融工具​

import asyncio

from nautilus_trader.adapters.tardis import TardisHttpClient


async def run():
    http_client = TardisHttpClient()

    instrument = await http_client.instruments("bitmex", symbol="xbtusd")
    print(f"Received: {instrument}")

    instruments = await http_client.instruments("bitmex")
    print(f"Received: {len(instruments)} instruments")


if __name__ == "__main__":
    asyncio.run(run())

在 Rust 中请求金融工具​

完整示例见 crates/adapters/tardis/bin/example_http.rs。

use nautilus_tardis::{
    common::enums::TardisExchange,
    http::TardisHttpClient,
};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    nautilus_common::logging::ensure_logging_initialized();

    let client = TardisHttpClient::new(None, None, None, true, None)?;

    // Tardis instrument definitions
    let info = client
        .instruments_info(TardisExchange::Bitmex, Some("XBTUSD"), None)
        .await?;
    println!("Received: {info:?}");

    // Nautilus instrument definitions
    let instruments = client
        .instruments(
            TardisExchange::Bitmex,
            Some("XBTUSD"),
            None,
            None,
            None,
            None,
            None,
            None,
        )
        .await?;
    println!("Received: {instruments:?}");
    Ok(())
}

Nautilus 数据客户端​

TardisDataClientConfig 与 TardisDataClientFactory 把配置好的 Tardis Machine 数据流接入 Nautilus 节点。配置选择其中一种模式：

  • options 列表非空时，连接历史的 ws-replay-normalized 端点。
  • options 为空时，非空的 stream_options 列表连接实时的 ws-stream-normalized 端点， 并在可恢复的中断后自动重连。

两个列表必须有且仅有一个非空。若两者都设置，options 选择历史回放模式。这些请求选项决定了上游 交易所、符号与数据类型。Nautilus 的订阅命令不会增删 Tardis Machine WebSocket 上的数据。

options 为空时，stream_options 中的 BitMEX 条目会在任何网络请求之前失败。BitMEX 回放请用 历史的 options。来自 Tardis Machine 的"交易所不受支持"关闭会让实时数据流终止且不再重连。

数据客户端会为每个配置好的请求加上 derivative_ticker，以便在数值变化时发布资金费率、标记价格与 指数价格。它也支持支持的格式中的其他输出，包括 OptionGreeks 以及来自 option_summary 消息的可选 BBO QuoteTick 数据。

从 Tardis JSON 构造 Python 的流选项，再传给公共的数据客户端配置：

from nautilus_trader.adapters.tardis import StreamNormalizedRequestOptions
from nautilus_trader.adapters.tardis import TardisDataClientConfig
from nautilus_trader.adapters.tardis import TardisDataClientFactory


stream_options = StreamNormalizedRequestOptions.from_json(
    b'{"exchange":"binance-futures","symbols":["BTCUSDT"],"dataTypes":["trade","quote"]}',
)
config = TardisDataClientConfig(stream_options=[stream_options])
factory = TardisDataClientFactory()

把 factory 与 config 传给 LiveNode.builder(...).add_data_client(...)。节点注册模式见 examples/live/tardis/data_tester.py，完整的 Rust 回放客户端见 crates/adapters/tardis/examples/node_data_tester.rs。

Rust 数据客户端配置可以把 book_snapshot_output 设为 depth。Python 数据客户端配置使用默认的 deltas 输出。独立的回放 JSON 配置两种取值都支持。

成交 ID 的推导​

成交 tick 使用 Tardis 消息或 CSV 行中交易场所提供的成交 ID 作为 TradeId。交易场所省略成交 ID 时 （部分交易所为空字符串或 null），两个解析器都使用确定性的 FNV-1a 哈希。哈希包含符号、时间戳、价格、 数量和方向。价格与数量按十进制值哈希，因此同一事件在两个解析器中会推导出相同的 ID，前提是其 CSV 值 经 f64 往返后不变。同一交易场所事件在多次回放中产生相同的成交 ID，从而保持下游去重有效。

限制与注意事项​

TardisDataClient 不实现 Nautilus 的数据请求，包括金融工具、订单簿、报价、成交、资金费率和 K 线 请求。通过 options 配置历史回放，或用 run_tardis_machine_replay 走 catalog 工作流。

测试 Tardis Node 兼容性​

Deribit 回归测试把一份快照、已被覆盖的排队增量和一条新增量喂给已安装的 Tardis Node 归一化器， 然后检查完整的 Nautilus 订单簿。它需要与所测试的 tardis-dev 包兼容的 Node.js，并独立于默认 Rust 测试运行。在仓库根目录执行：

tardis_test_dir=$(mktemp -d)
npm install --prefix "$tardis_test_dir" --ignore-scripts --no-audit --no-fund tardis-dev@18.2.2
TARDIS_NODE_MODULE="$tardis_test_dir/node_modules/tardis-dev" \
  CARGO_BUILD_JOBS=4 NEXTEST_TEST_THREADS=4 cargo nextest run --locked -p nautilus-tardis \
  --cargo-profile nextest --run-ignored only -E 'test(test_deribit_snapshot_queued_updates_with_tardis_node)'
rm -rf "$tardis_test_dir"
